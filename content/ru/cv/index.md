**OpenTalon — платформа LLM-оркестрации для enterprise (github.com/opentalon)**

- Роутинг без привязки к вендору между OpenAI, Anthropic Claude и DeepSeek: модель выбирается под задачу по качеству, latency и стоимости, с fallback и единым интерфейсом — экономика на токенах без vendor lock-in.
- Построил путь оценки, который делает решения о роутинге защитимыми: одна и та же нагрузка прогоняется по провайдерам и сравнивается по качеству ответа, p95 latency и стоимости задачи, а не по вендорским бенчмаркам.
- Prompt injection prevention: каждый запрос проходит security-проверку до вызова модели, guard-плагины санитизируют tool-результаты прежде, чем их увидит модель — закрывает главный риск OWASP LLM Top 10, и одна скомпрометированная интеграция не может отравить контекст или дотянуться до других плагинов.
- Принцип архитектуры «LLM пишет код, runtime держит его безопасным» (по мотивам Cloudflare Code Mode for MCP): модель выдаёт сценарии на ограниченном DSL, грамматика которого не может выразить небезопасную операцию — структурный sandbox вместо политики, которой мы надеемся, что модель следует.
- Изоляция плагинов: каждый плагин — отдельный OS-процесс за gRPC + Protobuf, поэтому ядро сохраняет свою память, а плагины не могут эскалировать привилегии или двигаться латерально.
- Channel-aware аутентификация для корпоративных мессенджеров (Teams / Slack): доступ к данным и инструментам скоупится по каналу и пользователю.
- MCP как источник фактов для агентов и host-scheduler для периодических задач.

**Talooner — AI-ревью кода для агентской разработки (talooner.com)**

- Внедрил end-to-end в две компании: discovery, проектирование политики на их гайдах и ownership-правилах, тесты правил, CI-workflow, пилот на реальных PR. Ревью идёт в инфраструктуре клиента; код и диффы не покидают контур, токен форжа живёт один прогон.
- Продуктовая модель: детерминированное ревью PR/MR для GitHub и GitLab. Политика — версионируемый ruleset на `tln` в репозитории клиента, читается из base-ветки, поэтому PR не может переписать правила, по которым его судят.
- Модель вызывается только там, где об этом просит правило (`do llm_review`), а её ответ возвращается в движок фактом: один коммит плюс один ruleset дают один вердикт, повторный прогон — cache hit без расхода токенов.
- Онбординг сам является агентом (talooner-skills): интервьюирует заказчика о чувствительных путях, пишет первый ruleset, тесты и workflow, открывает draft PR.
- Бенчмарк на реальном MR (200 файлов, +7 000 / −1 000 строк): ~30 с и ~$0.10 против $5.5–28 у ревью чат-моделью; на 20 файлах — 14 с против примерно 40 минут ревью сеньора.
- Метрики `talooner_*` в Prometheus и дашборд Grafana: auto-approval rate, стоимость LLM на ревью, разрез по плагинам и моделям.

**tln — DSL и движок правил (github.com/opentalon/tln-language)**

- Компилятор и рантайм на Go: lexer, parser, validator, query planner, инференс над фактами. Правила читаются как английский, поэтому доменный эксперт пишет и аудитирует их без программирования.
- FactStore на Datalevin (Datalog, full-text search): каждое срабатывание объяснимо, отдаётся trace из фактов, правила и порога — no black box.
- ML-примитивы (anomaly detection, forecasting, clustering, classification) как ключевые слова языка: миллисекунды на структурированных данных, пороги обучаются на данных тенанта.
- Expert-in-the-Loop: LLM отвечает за язык и намерение, движок — за факты, инференс и политики. Целевые домены — compliance-heavy: финансы, страхование, healthcare — и обслуживание активов.
